The Myth Of Less Code Is Better In Programming Languages

In the world of programming, many developers compare Python to other languages, often highlighting the advantage that Python allows you to "write less code." While this may sound appealing, it's essential to understand that writing less code does not inherently make a language better or easier to read. And they end up saying, this language is good for beginners, not knowing that every language is good for starting out.

First, let's look at the language which in my opinion is the best language for beginners: BASIC, the Beginner's All-Purpose Symbolic Instruction Code. This is usually expected to focus on the programming logic and not worry about resources and other issues.

Important: I intentionally do not highlight the example codes :)

' Program to add two numbers in BASIC

INPUT "Enter the first number: ", num1

INPUT "Enter the second number: ", num2

sum = num1 + num2

PRINT "The sum of "; num1; " and "; num2; " is "; sum

What do you think? Is it a lot of code? Is it difficult to understand? Wait! Let's cause a little headache. COBOL!, come here:

IDENTIFICATION DIVISION.
PROGRAM-ID. ADD-NUMBERS.

DATA DIVISION.
WORKING-STORAGE SECTION.
	01 NUM1       PIC 9(4).
	01 NUM2       PIC 9(4).
	01 SUM        PIC 9(5).

PROCEDURE DIVISION.
   DISPLAY "Enter the first number: " WITH NO ADVANCING.
   ACCEPT NUM1.

   DISPLAY "Enter the second number: " WITH NO ADVANCING.
   ACCEPT NUM2.

   COMPUTE SUM = NUM1 + NUM2.

   DISPLAY "The sum of " NUM1 " and " NUM2 " is " SUM.

   STOP RUN.

Don't be scared. Let's see then in the much acclaimed Python:

# Program to add two numbers in Python

num1 = int(input("Enter the first number: "))

num2 = int(input("Enter the second number: "))

sum = num1 + num2

print(f"The sum of {num1} and {num2} is {sum}")

As you can see, the number of lines of code is not a decision variable in this case. What follows is pure C code, not C++, and maybe someone will get dizzy when seeing a main function:

#include <stdio.h>

// Program to add two numbers in C
int main() {
    int num1, num2, sum;

    printf("Enter the first number: ");
    scanf("%d", &num1);

    printf("Enter the second number: ");
    scanf("%d", &num2);

    sum = num1 + num2;

    printf("The sum of %d and %d is %d\n", num1, num2, sum);

    return 0;
}

Less code or black box?

Is C harder to read? Or are we reading code that is more verbose and less black box? So let's turn that into a black box. With this library we can simplify data entry and reduce lines:

custom_io.h

#ifndef CUSTOM_IO_H
#define CUSTOM_IO_H

void input(const char* prompt, const char* format, void* var);
void print(const char* format, ...);

#endif // CUSTOM_IO_H

custom_io.c

#include "custom_io.h"
#include <stdarg.h>
#include <stdio.h>

void input(const char* prompt, const char* format, void* var) {
    printf("%s", prompt);
    scanf(format, var);
}

void print(const char* format, ...) {
    va_list args;
    va_start(args, format);
    vprintf(format, args);
    va_end(args);
}

The first transformation of our program would be like this:

#include "custom_io.h"

int main() {
    int num1, num2, sum;

    input("Enter the first number: ", "%d", &num1);
    input("Enter the second number: ", "%d", &num2);

    sum = num1 + num2;

    print("The sum of %d and %d is %d\n", num1, num2, sum);

    return 0;
}

If you want more brevity, you can get it:

// custom_io.h

int input_int(const char* prompt);

// custom_io.c

int input_int(const char* prompt) {
    int value;
    input(prompt, "%d", &value); // Usa la función input interna
    return value;
}

And then I got almost the same clarity as Python and BASIC:

#include "custom_io.h"

int main() {
    int num1 = input_int("Enter the first number: ");
    int num2 = input_int("Enter the second number: ");

    int sum = num1 + num2;

    print("The sum of %d and %d is %d\n", num1, num2, sum);

    return 0;
}

We reduce, but we can also amplify

In the end it all ends up being this in some way, even more so when it comes to machine code. Let's use NASM (Netwide Assembler) on Linux. Now you'll get dizzy and tired:

section .data
    prompt1 db 'Enter the first number: ', 0
    prompt2 db 'Enter the second number: ', 0
    result_msg db 'The sum of ', 0
    newline db 0xA, 0
    num1 db 0         ; Variable to store the first number (in ASCII)
    num2 db 0         ; Variable to store the second number (in ASCII)
    sum_msg db ' and ', 0
    sum_result db ' is ', 0

section .bss
    sum resb 4        ; Variable to store the sum (in ASCII format)

section .text
    global _start

_start:
    ; Prompt the user for the first number
    mov eax, 4            ; syscall number 4: sys_write
    mov ebx, 1            ; file descriptor 1: stdout
    mov ecx, prompt1      ; address of the message
    mov edx, 22           ; length of the message
    int 0x80              ; call the system

    ; Read the first number
    mov eax, 3            ; syscall number 3: sys_read
    mov ebx, 0            ; file descriptor 0: stdin
    mov ecx, num1         ; address to store input
    mov edx, 1            ; length of input
    int 0x80              ; call the system

    ; Prompt the user for the second number
    mov eax, 4            ; sys_write
    mov ebx, 1            ; stdout
    mov ecx, prompt2      ; address of the message
    mov edx, 23           ; length of the message
    int 0x80              ; call the system

    ; Read the second number
    mov eax, 3            ; sys_read
    mov ebx, 0            ; stdin
    mov ecx, num2         ; address to store input
    mov edx, 1            ; length of input
    int 0x80              ; call the system

    ; Convert the ASCII characters to integers by subtracting '0'
    sub byte [num1], '0'
    sub byte [num2], '0'

    ; Add the two numbers
    movzx eax, byte [num1]  ; load num1 into eax
    add eax, [num2]         ; add num2

    ; Convert the result back to ASCII
    add eax, '0'
    mov [sum], al

    ; Display the result
    mov eax, 4              ; syscall sys_write
    mov ebx, 1              ; stdout
    mov ecx, result_msg     ; message
    mov edx, 12             ; length of the message
    int 0x80                ; call the system

    mov eax, 4              ; sys_write to display the first number
    mov ebx, 1
    mov ecx, num1           ; the first number converted
    mov edx, 1              ; length of the number
    int 0x80

    mov eax, 4              ; display " and "
    mov ebx, 1
    mov ecx, sum_msg
    mov edx, 5
    int 0x80

    mov eax, 4              ; sys_write to display the second number
    mov ebx, 1
    mov ecx, num2           ; the second number converted
    mov edx, 1
    int 0x80

    mov eax, 4              ; display " is "
    mov ebx, 1
    mov ecx, sum_result
    mov edx, 4
    int 0x80

    mov eax, 4              ; sys_write to display the sum
    mov ebx, 1
    mov ecx, sum            ; result
    mov edx, 1              ; length of the result
    int 0x80

    mov eax, 4              ; new line
    mov ebx, 1
    mov ecx, newline
    mov edx, 1
    int 0x80

    ; Exit the program
    mov eax, 1              ; syscall number 1: sys_exit
    xor ebx, ebx            ; exit code 0
    int 0x80

Short syntax or different purpose?

One common point of comparison is the use of semicolons to terminate statements. Languages like C++ require a semicolon at the end of each statement, while Python does not. At first glance, it might seem like Python is simpler because it has fewer syntactical requirements.

However, the absence of semicolons doesn't necessarily make Python objectively easier to read. In both cases, the programmer needs to be aware of where a statement ends—whether it's marked by a semicolon or a newline character. The cognitive load is similar; it's just a different convention.

The idea that writing less code is always better sounds appealing but can sometimes be a sign of laziness. If the syntax is sufficiently descriptive, the length of the code should not matter.

Consider reading books or poems: a concise news summary might be ideal for those who want to quickly get the gist of current events, but a novel requires detailed descriptions to immerse the reader in the story. Similarly, in programming, clarity and descriptiveness are often more important than brevity.

There's a misconception, especially among beginner programmers, that writing less, using indentation, and avoiding semicolons is universally better. This belief ignores the complexity and richness that detailed and descriptive code can offer.

Moreover, Python is not the only language that doesn't require semicolons. Several other languages, such as Ruby and Swift, also omit this requirement, proving that the absence of semicolons is not a unique advantage of Python but rather a design choice present in various programming languages.

While Python is more concise and its syntax is simpler, the C version may appear more explicit and, for some, easier to understand in terms of how resources are managed and data is manipulated. C can offer a more detailed view of low-level control, which in certain contexts makes the code easier to follow and debug.

The example can help illustrate how brevity in code does not always equate to clarity or better maintainability, and how the greater explicitness in C might be preferable in some cases.

Hello, World!

In the world of programming, brevity in code is often celebrated, but as we've seen, it doesn't always equate to better readability or maintainability. The choice of language and the approach to solving a problem can significantly impact how understandable and manageable the code is in the long run. Ultimately, the cleanest code is often the one you don't have to write—where simplicity and thoughtful design eliminate the need for unnecessary complexity.

Every language has a purpose. So many of these claims that language A is better understood than language B end up being useless. You can't compare English to American Sign Language. Furthermore, sometimes you want brevity and other times you want detail.

And the first code many people teach beginners, as a flag of simplicity and clarity, is a Hello World example. In Python:

Ok. So the beginner understands what the program is trying to do.
